# Production audit — 2026-10-26 (Phase A)

Branch `feat/production-audit-phase-a`, based on `main` at `ca0305d`.

Phase A covers the repository audit, a baseline, and fixes for the highest-priority
confirmed defects. Phases B–J (offline-first rework, ranking engine, PWA, and the
rest) are **not started**. Nothing here was deployed, migrated, or run against
production.

## 1. Architecture (verified)

```
 Expo app (Android / iOS / Web)            Admin panel (Vite SPA)
 expo-router, React Query (memory only),   Firebase admin token
 WatermelonDB: SQLite (native) /                    │
 LokiJS+IndexedDB (web), AsyncStorage               │
        │  Firebase ID token                        │
        ▼                                           ▼
 ┌──────────────── Cloudflare Worker `tophunt-api` (Hono) ────────────────┐
 │ /read/* public+viewer reads   /api/* actions   /admin/* role-gated     │
 │ /webhook/razorpay|bunny       /ws realtime     /media/* (legacy R2)    │
 │ D1 `tophunt-db` (self-migrating, 65 migrations)   KV CACHE_KV, OTP_KV  │
 │ Durable Objects: rate limiter, vote counter, realtime/chat             │
 └───────────────┬───────────────────────────────┬────────────────────────┘
                 ▼                               ▼
   R2 `tophunt-media` @ media.tophunt.in   Bunny Stream (video), Razorpay
```

Source of truth today: the server owns balances, votes, settlement, permissions
and payment state. The client holds caches only: a Story cache and a pending
view/reaction queue (WatermelonDB), a 16-item Home snapshot, and memory-only
React Query. The pending queue refuses every action type except Story `view`
and `reaction`, so money, votes and contest joins cannot be queued.

# Phase B: cross-platform local database foundation

Branch `feat/production-audit-phase-b`, stacked on Phase A. The full policy now
lives in [`docs/LOCAL_DATA.md`](docs/LOCAL_DATA.md): source of truth, tables,
bounds, account scoping, the never-persist list, failure handling and platform
status.

## B.1 What was there already

- One WatermelonDB database. Native uses the SQLite adapter and web uses LokiJS + IndexedDB, picked per platform by Metro.
- Schema v5 with 4 tables and additive migrations v2–v5.
- Screens never import the database. Only two services and the launch housekeeping do.
- The pending queue is bounded (200 rows, 7 days) and limited to replay-safe Story views and reactions.

Given that, I did **not** add a new repository layer or move more data types
(chat, notifications, comments) into the database. Each of those needs a
server sync contract, which belongs in Phases C and F, and adding tables now
would only create more caches to keep coherent.
